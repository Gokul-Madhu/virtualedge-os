# VirtualEdge v0.14 — mTLS development gateway release notes

## Implemented

- WSL-hosted loopback-only, Python standard-library HTTPS gateway.
- TLS 1.2 minimum, OpenSSL-backed certificate validation, mandatory client certificates.
- Temporary local development CA with server and client certificates, generated by an explicit provisioning command; no credentials in source.
- Read-only route allowlist to VirtualEdge dashboard, telemetry, diagnostics, device status, metrics and readiness.
- Validates server-key permissions; refuses to overwrite generated keys.
- Optional pass-through of the guest's existing HTTP Basic auth with `--forward-basic`.
- Dedicated full HTTPS integration tests against a loopback mock API.

## Verified in this environment

- `python3 tests/test-tls-gateway.py`: passed.
- `python3 tests/test-auth.py`: passed.
- `python3 tests/test-readiness.py`: passed.
- Python compile checks and shell syntax: passed.
- `./scripts/test-host.sh` progressed through diagnostics, API, hardening, process supervisor, physical temperature simulation fixtures, device config, signed releases and persistence tests. It reached the existing A/B suite but exceeded the available execution window. Therefore full-suite completion is **not claimed**.

## Not verified / not implemented

- v0.14 ARM64 Buildroot compilation and physical QEMU guest acceptance.
- TLS running directly in the ARM64 guest; gateway intentionally runs on WSL host.
- Device-side certificate provisioning and lifecycle, trust-anchor rotation, certificate revocation, audit trail, secure remote network exposure, user roles or hardening certification.
- A/B OTA installation, hardware-backed secure boot and industrial qualification.
